## Priority issues

### P0 — BLOCKING: 10s poll destroys in-flight form edits (→ /impeccable harden)
While Servers tab is open, the poll (L648-651) calls loadServers, which unconditionally clear()s and rebuilds guildSettingsForm (L389). Typing a 19-digit snowflake takes >10s: unsaved edits vanish mid-form, no warning. Every guild-settings save is a race against the clock.
**Fix:** skip the rebuild when the form contains a focused element or any input differs from its loaded value (dirty flag set on input, cleared after save). Pure portal.js JS.

### P1 — "Reset overrides" is destructive, mislabeled, unguarded (→ /impeccable clarify)
Fires on one click (L436-440) with no confirm, and the handler also wipes per-guild command toggles and per-guild usage stats (L1369-1371) — the label undercounts the blast radius. Peak-end on a bad day: "I lost my play counts and nobody warned me."
**Fix:** confirm() naming exactly what is replaced (mirror the restore confirm at L600), rename button "Reset this server". No deps needed.

### P1 — Tri-state typed as 'true'/'false' text; silent coercion + silent truncation (→ /impeccable harden)
tri() (L416) maps ANY unrecognized string to false — 'ture' silently saves Off. Blank=inherit is indistinguishable from cleared after save. Server slices without a word back: prefix slice(0,5) (L1331), autoRoleIds slice(0,5) (L1447), welcomeMessage slice(0,400).
**Fix:** 3-option selects (Inherit/On/Off) via the existing el() pattern (L451-455); maxlength=5 on prefix; return "kept first 5 IDs" in the POST response on slice.

### P1 — Failure feedback is a 2.5s toast that leaves the UI lying (→ /impeccable polish)
Toast (L235-236, L720) has no role=status/aria-live — screen readers announce nothing; success and failure are indistinguishable to Sam. Failed settings change leaves the rejected value on screen (L567-570); failed per-guild select never reverts (L461) while the global checkbox does (L537) — same concept, opposite behavior.
**Fix:** role=status aria-live=polite; keep error toasts until next action; on post() failure re-run the owning tab's loader; share one toggle-failure helper.

### P2 — Keyboard/a11y + state persistence (→ /impeccable audit)
field() builds labels with no for/htmlFor (L393-395) — nine guild inputs unlabeled to AT; override selects have no accessible name; tab bar is 6 bare buttons, selection conveyed only by class .on (L289); no :focus-visible rule; refresh/tab-change loses tab+guild selection (in-memory only, L282). Login card overflows at 375px.
**Fix:** label.htmlFor + input.id; aria-label on selects; role=tablist + aria-selected; persist tab+guildId in location.hash; constrain login card width.

## Strengths
1. Empty/loading states everywhere in the product's lowercase voice ("the bot is in no servers" L374, "nothing has been changed through this portal yet" L640, "…and N more beyond row 50" L513) — zero-guild handled gracefully where most admin panels die.
2. Operator-grade microcopy: SETTINGS_SCHEMA hints name the escape hatch (L67-104); validation copy is prescriptive (L1342); securityNotes self-audit honestly admits plain http (L1249-1252).
3. Architecture-level trust: remote text only via textContent (L39-40), restore validates the whole bundle before touching disk (L1461-1471), audit failures never fail the change, active-overrides card makes the config layer inspectable — a direct UI expression of the local-first principle.

- **Sam:** toast-only feedback invisible to SR; 9 unbound labels; tab selection unannounced; poll rebuilds form under the caret; 11px badges and white-on-blurple sit on the AA line.
- **Riley:** music buttons never disabled in flight (double-click skip skips two); refresh = total state loss; 'ture' coerced silently; sliced input ≠ shown input; on save failure the select shows a value the server rejected. (Rewarded: honest zero/overflow states everywhere.)
